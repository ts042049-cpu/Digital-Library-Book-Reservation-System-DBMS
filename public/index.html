CAMPUS CENTRAL LIBRARY - ISSUE SLIP
Circulation Desk Validation Rules

1. Physical Copy Validation: The system strictly blocks issuing any title when available_copies = 0.

2. Active Member Status: Suspended or expired cardholders cannot borrow books until clearance.

3. Quota Constraint: Students can borrow a maximum of 4 books simultaneously; Faculty are permitted 8 books.

4. Automatic Stock Update: The book's available_copies attribute is automatically decremented atomically within an ACID transaction.

5. Overdue Fine Policy: Late returns accrue a penalty of ₹5.00 / day past the recorded due date.

DBMS Course Project Architecture & Viva Guide

Relational model specifications, normalization, integrity constraints, and query documentation

Relational Schema (Based on Draw.io ER Design)

1. BOOK (book_id, isbn, title, author, publisher, publication_year, genre, total_copies, available_copies, shelf_location)

2. MEMBER (member_id, member_code, full_name, email, phone, address, membership_type, membership_date, status, max_borrow_limit)

3. STAFF (staff_id, staff_code, full_name, email, phone, role, hire_date, password, status)

4. LOAN (loan_id, #book_id, #member_id, #staff_id, issue_date, due_date, return_date, status, fine_amount, fine_paid, remarks)

5. RESERVATION (reservation_id, #book_id, #member_id, reservation_date, status)

6. AUDIT_LOGS (log_id, action_type, description, staff_name, timestamp)

Relational Integrity & Normalization

Normalization (3NF / BCNF): All attributes depend directly on the primary key (no partial or transitive functional dependencies). Multi-valued attributes like multiple copies are managed via normalized counts and distinct loan transactions.

ACID Transaction Guarantee: During loan issue, book stock reduction and loan record insertion run inside a single atomic transaction. If stock check fails, the transaction is rolled back immediately.

Integrity Constraints: CHECK(available_copies <= total_copies), FOREIGN KEY ... ON DELETE RESTRICT prevents orphaned loan history.
